# Contributing to Nixxa

Thanks for helping. Nixxa is a sandboxed TUI harness for an AI agent, written in Rust and built
from blackbox modules. This page is the short version; [AGENT.md](AGENT.md) has the full rules,
and they apply to humans and AI agents alike.

## Finding something to work on

- Issues labelled [`good first issue`](https://github.com/Sahildhillon0/nixxa-harness/labels/good%20first%20issue)
  are small and self-contained; [`help wanted`](https://github.com/Sahildhillon0/nixxa-harness/labels/help%20wanted)
  ones are bigger or need something we don't have (a Windows machine, an API key).
- **Comment on the issue before you start**, so two people don't take the same one. For anything
  not covered by an issue, open one first and describe what you want to change.
- The roadmap is in [ARCHITECTURE.md](ARCHITECTURE.md) (§ Stages). Please don't build ahead of the
  current stage: ideas for later go under Open questions in [DESIGN.md](DESIGN.md).

## Setting up

- Rust **1.85** or newer (the MSRV; CI checks it).
- Linux, macOS or Windows. The real sandbox is Linux only for now and needs
  [bubblewrap](https://github.com/containers/bubblewrap) and unprivileged user namespaces. Without
  `bwrap` its tests print a loud `SKIPPED` banner instead of failing. On Ubuntu, AppArmor blocks
  unprivileged user namespaces; CI runs
  `sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0` first.
- Build and run: `cargo build -p nixxa-sandbox --bin nixxa-sandboxd && cargo run -p nixxa-harness`.
  `cargo run -p nixxa-harness -- --fake` runs a scripted agent: no account, no network, no
  history written.

## The rules that matter most

1. **Modules import only `contracts`.** `harness` alone wires the others together.
   `./scripts/check-deps.sh` enforces it.
2. **One module per change.** If a change needs two modules, it's a contract change: make the
   `contracts` change first, in its own commit, with ARCHITECTURE.md §3 updated in the same
   commit, then one commit per module.
3. **No `unsafe`**, no printing from library crates (use `tracing`), no weakening of the sandbox
   to make something work.
4. **Secrets go through `accounts` only.** They never reach the sandbox, logs, the database or the
   model's context. Never use real credentials, a real vault or a real memory database in tests.
5. **Docs move with code.** A decision gets a row in DESIGN.md §5; a contract change updates
   ARCHITECTURE.md §3; a UX change updates DESIGN.md §4.

## Tests

- Every trait implementation runs its suite from `nixxa_contracts::conformance`.
- A fix comes with a test that fails without it. For security-relevant changes, say in the PR
  which tests fail when the fix is removed ("break-to-fail").
- Before opening a PR, run the full gate, which is what CI runs on Linux, macOS and Windows:

  ```sh
  cargo fmt --all --check && cargo clippy --workspace --all-targets --all-features -- -D warnings && cargo test --workspace --all-features && ./scripts/check-deps.sh
  ```

## Commits and pull requests

- Conventional commits scoped by module: `feat(sandbox): …`, `fix(harness): …`,
  `docs(architecture): …`. One module per commit wherever possible.
- No AI co-author or "generated by" trailers.
- Branch from `main` and open the PR against `main`. Say what changed, why, how you tested it,
  and link the issue. CI must be green on every OS and on the MSRV.
- Every PR is reviewed before it's merged; for sandbox or security changes expect the reviewer to
  try to break it.

## Security

If you find a way out of the sandbox, a way to leak a secret, or a way for the agent to act
without approval, please don't open a public issue. Report it privately through GitHub's
[security advisories](https://github.com/Sahildhillon0/nixxa-harness/security/advisories/new).
